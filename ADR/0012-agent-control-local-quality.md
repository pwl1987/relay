# ADR-0012：受控 Agent 干预与本地优先质量验证

状态：**ACCEPTED（架构原则） / OPEN（实现与性能数值）**
日期：2026-11-13
关联：ARCHITECTURE_BASELINE.md、CONTRACTS.md、docs/AGENT_CONTROL_LOCAL_QUALITY.md、ADR-0003/0004/0007/0008。

## 背景

Relay 已具备 PostgreSQL + Worker + Pi RPC + Gate + GitHub 的最小交付链，但当前会话为短 Run，缺少人类接管、计划修订和多 Agent 运行态统一控制。
现有 CI 已覆盖类型、单测、真 PostgreSQL 与浏览器路径，部分受保护模型/基础设施测试可 skip；尚未建立一套本地/云端统一的格式、Lint、机器证据底线和性能准入。
用户希望本地可独立 CI、可信质量、进度和接管，且保持 Pi 生态兼容、main-only、单 Writer 和最小实现。

## 决策

1. Relay Core 继续独占 Goal/Task/Run/计划版本/权限/租约/预算/Gate 的持久事实与最终裁决，Pi 只负责有界 AI 执行和局部子 Agent 能力。
2. 定义观察、指导、暂停、紧急停止、人工接管、交还 AI 六种不同操作；指导的 ACK 与真正生效必须分离；人工接管前撤销旧写入资格并核查副作用。
3. 计划方向变化先生成不可变修订记录并栅栏旧任务；终态 Goal 的普通会话不得隐式创建新 READY Task。
4. 并行只读、唯一 Writer；子 Agent 权限及预算只可收紧，父子取消传播和独立审查可验证。
5. 本地质量验证为一等执行入口，GitHub Actions 提供独立外部复核；优先共享同一检查命令及锁定配置，不增另一套 CI 编排服务。
6. 采用快速/完整/发布三级检查；只读格式与静态检查、类型、机器测试、独立 Reviewer、风险触发性能/安全检查共同进入原有 Gate。
7. 代码变更的最低机器测试证据不能仅由 reviewer_output 顶替；必需检查 NOT_RUN/SKIPPED 视作未满足门槛，例外必须由确定性规则有证据判为不适用。
8. 不按总评分或最短代码行数自动验收；最小必要复杂度优先，性能以可复现基线测量后冻结阈值。
9. 生产 Pi 精确版本锁定，按上游候选升级实测；pstack 仅选择性复用工程方法，不引入第二调度、自动分支或权限系统。
10. 优先确定性程序处理权限、预算、调度、状态、恢复与验收，模型用于理解、规划、编码和分析，不可替代强制安全门。

## 否决的替代方案

- 完全弃用 GitHub CI：降低环境独立复核能力，且对公开仓库通常无必要。
- 在生产 VM80 部署公开仓库的常驻 self-hosted Actions Runner：增大高权限宿主暴露面。
- 为编排/质量/评分建立新常驻服务：与现有 Core、Gate 重复，增加故障面与维护成本。
- 一次性全量集成 pstack/多 Agent 并行写、强制全量性能压测：违反当前唯一 Writer 或成本/稳定性原则。
- 让模型自行判断权限、批准安全门或自报进度百分比：缺乏可重复机器证据。

## 可执行前置条件

本 ADR 接受的是设计边界，不表示功能已经实现。后续通过独立 WorkPackage 实现前，必须取得唯一 Writer、冷启动核实、明确测试授权、风险隔离与回滚。
新增 Agent 控制需要至少测试运行中 steer/abort、工具未结束、断线重连、重复命令、接管时旧 Run 仍活跃、重规划后旧栅栏无效。
新增质量门需要验证缺失/skip/失败测试不被误放行，Git SHA/环境变更使旧证据失效，本地检查与 GitHub 检查一致。
P0 仍允许明确范围的现有纵向路径继续；不得因本 ADR 把尚未实现的 P1 Agent Session 能力称为 MVP 已验收。
