**B 的启动方法(在 VM80 上跑一条命令)**:

```bash
node scripts/webux11-preview.mjs          # 启动后会打印一次性登录口令(仅打印一次)
```

## 二、验收旅程(照着做一遍;三条可直接复制的测试需求)

登录后你应看到:大标题「今天想让 Relay 做什么?」、下方一个输入框和一个蓝色「开始」按钮(空白态**只有这一个**主按钮;没有项目时会提示「尚无项目:直接在下方输入一句话即可开始…」)。

**三条可复制的测试需求**(任选或都试):

1. `感觉登录页不好用,想让登录更快更清楚。`
2. `帮我把首页的标题文字调大一点,更显眼。`
3. `想给项目加一个暗色模式开关。`

**正常路径与预期反馈(每一步都应在同一会话内完成,不需要跳页)**:

| 你做什么 | 你应看到 |
| --- | --- |
| 输入一句话 → 点「开始」 | 自动进入会话;你的消息以蓝色气泡出现;下方出现「已纳入执行队列,即将开始 ○项目分析○代码修改○自动测试○独立复核○交付」进度块 |
| 等几秒(预览环境自动推进) | 进度块变成绿色「✓ Relay 已完成本轮工作」:代码修改/测试/独立复核/已提交 GitHub 各行打勾,附「查看修改」「技术详情」 |
| 继续在输入框说话 → 「发送」 | 消息保留在会话里;因为该需求已完结,Relay 回复「已记录…不会自动创建新执行任务;如需继续,请新建一个需求」(不会假装开始新一轮) |
| 需求完结后,输入新的一句话 → 点「新建后续任务」 | **真实创建一个新的后续需求**并自动进入它(按钮上没有「执行」字样,不会再点了没反应);旧需求的历史与结果原样保留,随时可点回去看 |
| (需求被暂停时)输入框下方应有一行提示「该需求已暂停…Relay 不会自动恢复」,且没有「执行/新建」按钮 | 不误导你点击;恢复走任务恢复操作,不自动暗启 |
| 点左下「＋ 新建任务」再提一个新需求 | 回到空白态,重复上面的旅程 |
| (如出现)黄色「⚠ 需要你的决定」卡 | 卡内写明问题/建议/风险/截止;点「允许 / 批准」→ 提示「✓ 已批准,Relay 继续执行」,执行自动继续(这是正确行为:Relay 未经你允许不扩权) |
| (如出现)红色「✗ 本轮工作未完成,需要处理」 | 卡内有「下一步」提示(查看原因/新建需求);点「查看原因」是技术细节,平时可忽略 |

**重点替你核过的四个首用障碍(本轮已修,验收时请特别留意)**:①空白态不再出现点了没反应的「交给 Relay 执行」按钮(旧版两个蓝按钮并列);②零项目时引导语不再说「选择项目」而是告诉你直接开始/去哪加项目;③失败时明说下一步(新建需求重试),不是只甩一个技术入口;④**需求完成后不再显示误导性的「交给 Relay 执行」**(点了其实不会执行),改为真实有效的「新建后续任务」;需求被暂停时给中文恢复指引、不暗启任务(2026-11-16 追加修复)。

## 三、A 与 B 的行为差异(避免误判)

- A(旧代码)没有「交给 Relay 执行」按钮和本轮修复;若你在 A 上看到空白态异常文案,以 B 为准。
- A 的需求完结后仍显示「交给 Relay 执行」但点了不会执行(误导);B 已改为「新建后续任务」真实创建新需求——这一项**只在 B 上验收**。
- B 的执行结果是**确定性桩**(几秒完成,修改的是临时工作区,交付到一次性本地仓库);「已提交 GitHub」指该隔离交付,与真实 GitHub 仓库无关。
- 预览环境没有项目注册表;想带项目体验可在启动前自行设置 `RELAY_PROJECTS_FILE`(见脚本头注释)。
