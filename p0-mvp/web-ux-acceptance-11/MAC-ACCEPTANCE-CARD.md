## 一、你可以看的两个东西(先分清,再体验)

| | A. 现役 Web(生产) | B. 最新 main 隔离预览(本轮) |
| --- | --- | --- |
| 是什么 | 真实生产服务,但运行的是**旧代码**(2026-11-13 启动的进程,PID 3242781 至今未变) | 最新 main 代码(含 11/11R/12/12R/13 全部修复),跑在**隔离一次性环境**(合成数据+确定性执行桩,零真实模型、零生产触碰) |
| 地址(Mac 浏览器) | `http://10.30.5.80:8787` | 见下方启动方法(经 SSH 端口转发,只在本机与 VM80 之间,不经公网) |
| 数据 | 生产真实项目/任务 | 空白新环境(真实「第一次打开」状态);执行由确定性桩完成(非真实模型,几秒出结果) |
| 用途 | 对照「现状基线」 | 验收「要交给你的最新体验」;**你的 Mac 验收以 B 为主** |

**B 的启动方法(在 VM80 上跑一条命令,前台)**:

```bash
node scripts/webux11-preview.mjs          # 启动后打印一次性登录口令(仅打印一次)
```

想限制时长(可选):`timeout 30m node scripts/webux11-preview.mjs --port 8790` —— 到 30 分钟自动退出并清理,不会长期占用。

然后在 **Mac** 终端建 SSH 隧道(端口按需改):

```bash
ssh -L 8790:127.0.0.1:8790 <你的VM80账号>@10.30.5.80
```

Mac 浏览器打开 `http://localhost:8790/workspace`,用上一步打印的口令登录。

**局域网直接访问(可选,14 包新增;免 SSH 隧道)**:在 VM80 上加 `--lan` 启动——

```bash
node scripts/webux11-preview.mjs --lan --port 8790
```

启动 banner 会打印全部局域网地址(本机实测主网卡为 `http://10.30.5.80:8790/workspace`;多网卡如实全列)。Mac(或同一网段的手机)浏览器**直接打开**该地址,用当次打印的口令登录。安全口径:仅限**可信局域网**;**严禁任何端口映射/反向隧道把预览暴露到公网**(LAN≠公网);登录仍需当次一次性随机口令;退出清理与下述完全一致。缺省(不加 `--lan`)仍仅绑 127.0.0.1。

**退出与清理(13 包已实证)**:VM80 上 `Ctrl+C`(或直接关闭那个 SSH 终端)⇒ 一次性数据库 schema 与 /tmp 临时目录**全部自动删除**、端口释放、进程退出——不留垃圾、不留后台进程、不碰生产任何东西。唯一例外:`kill -9` 式强杀无法拦截(诚实限制,一般用不到)。预览缺省只绑定 127.0.0.1;`--lan` 才放行局域网绑定(server 层守卫的显式机制),仍禁公网。

若不便起隧道:本轮附 8 张来自**同一预览脚本**的真实 Chromium 截图(桌面 1440+手机 390,`p0-mvp/mac-ux-handoff-13/screenshots/preview/`),可直接看图代替。

## 二、验收旅程(照着做一遍;三条可直接复制的测试需求)

登录后你应看到:大标题「今天想让 Relay 做什么?」、下方一个输入框和一个蓝色「开始」按钮(空白态**只有这一个**主按钮;没有项目时会提示「尚无项目:直接在下方输入一句话即可开始…」)。

**三条可复制的测试需求**(任选或都试):

1. `感觉登录页不好用,想让登录更快更清楚。`
2. `帮我把首页的标题文字调大一点,更显眼。`
3. `想给项目加一个暗色模式开关。`

**正常路径与预期反馈(每一步都应在同一会话内完成,不需要跳页)**:

| 你做什么 | 你应看到 |
| --- | --- |
| 输入一句话 → 点「开始」 | 自动进入会话;你的消息以蓝色气泡出现;下方出现「已纳入执行队列,即将开始 ○项目分析○代码修改○自动测试○独立复核○交付」进度块 |
| 等几秒(预览环境自动推进) | 进度块变成绿色「✓ Relay 已完成本轮工作」:代码修改/测试/独立复核/已提交 GitHub 各行打勾,附「查看修改」「技术详情」 |
| 继续在输入框说话 → 「发送」 | 消息保留在会话里;因为该需求已完结,Relay 回复「已记录…不会自动创建新执行任务;如需继续,请新建一个需求」(不会假装开始新一轮) |
| 需求完结后,输入新的一句话 → 点「新建后续任务」 | **真实创建一个新的后续需求**并自动进入它(旧需求的历史与结果原样保留,随时可点回去看) |
| (需求被暂停时)输入框下方应有一行提示「该需求已暂停…Relay 不会自动恢复」,且没有「执行/新建」按钮 | 不误导你点击;恢复走任务恢复操作,不自动暗启 |
| 点左下「＋ 新建任务」再提一个新需求 | 回到空白态,重复上面的旅程 |
| (如出现)黄色「⚠ 需要你的决定」卡 | 卡内写明问题/建议/风险;点「允许/批准」→ Relay 继续;这是正确行为:Relay 未经你允许不扩权 |
| (如出现)红色「✗ 本轮工作未完成,需要处理」 | 卡内有「下一步」提示(查看原因/新建需求);点「查看原因」是技术细节,平时可忽略 |

**重点替你核过的首用障碍(已修,验收时请特别留意)**:①空白态不再出现点了没反应的「交给 Relay 执行」按钮;②零项目时引导语直接告诉你如何开始;③失败时明说下一步;④需求完成后显示真实有效的「新建后续任务」而非误导的「执行」;⑤暂停时给中文恢复指引、不暗启任务(2026-11-16);⑥网络回执丢失后重试**同一需求同项目**会安全返回同一个 Goal,不会重复创建;换项目/换身份的重试会被 409 如实拒绝(2026-11-17);⑦预览正常需求几秒到绿色「已完成」,不再卡保守询问(2026-11-18)。

## 三、A 与 B 的行为差异(避免误判)

- A(旧代码)没有 11~13 的任何修复;若你在 A 上看到空白态异常文案或完成后误导的「执行」按钮,以 B 为准。
- B 的执行结果是**确定性桩**(几秒完成,修改的是临时工作区,交付到一次性本地仓库);「已提交 GitHub」指该隔离交付,与真实 GitHub 仓库无关。
- 预览环境没有项目注册表(真实「零项目」首用状态);想带项目体验可在启动前自行设置 `RELAY_PROJECTS_FILE`(见脚本头注释)。
