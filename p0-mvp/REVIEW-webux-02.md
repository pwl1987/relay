## 三、发现列表

### Major

**M1. 验收结果主路径出现英文枚举 `NONE`(违反"状态全部中文"门)**
- 位置:`/home/ubuntu/dev/relay/web/changeset.js:17-18`(`deliveryLabel` 映射表缺少 `NONE` 键,回退到 `A.zh()`);`/home/ubuntu/dev/relay/web/changeset.js:234`("全部结果"表状态列直接 `A.zh(c.deliveryState)`);根因:`/home/ubuntu/dev/relay/web/app.js` `ZH_STATUS` 表未登记 `NONE`(已 grep 确认无该键),`zh()` 对未登记值原样直出(app.js:147-151)。
- 现象(截图证据):d5/p5 中"GitHub"行显示灰色徽章 `NONE`,"全部结果"表状态列显示 `NONE`。这是普通用户查看交付结果的必经路径,不是技术详情区。
- 建议修复:在 `deliveryLabel`(或 `ZH_STATUS`)补 `NONE: "尚未交付"`(或"未交付"),并同步 `stateKind` 给中性色;技术详情区(变更集交付状态行,changeset.js:176)保持"中文徽章 + 原始枚举并列"的现有正确模式即可。

### Minor

**m1. p2-390-drawer.png 为动画中间态,不能作为抽屉验收证据**
- 位置:`p0-mvp/webux-02/screenshots/p2-390-drawer.png`;相关实现 `web/style.css:370-377`(`translateX(-100%)` + `transition: 0.18s`)。
- 问题:截图里抽屉仅展开约 90px,导航文字全部被裁切、无遮罩层;无法证明展开后的抽屉导航完整可用。代码上完全展开为 246px、有阴影,大概率是截屏时机落在 0.18s 过渡窗口内。
- 建议:过渡结束后再截(或截图脚本等待 `.sidebar.open` 稳定),重新出具该张证据;顺带评估是否需要点击外部区域关闭/遮罩(当前无 backdrop)。

**m2. 手机 390px 下"全部结果"表格拥挤,"查看 →"链接逐字竖排断行**
- 位置:p5-390-result.png;对应 `web/changeset.js:240` 附近的结果表渲染与 `style.css` 移动端表格样式(仅缩字号,未改布局)。
- 问题:三列表格在 390px 下 UUID 折成四行,"查看 →"被断成"查/看/→"竖排,点击目标极小。
- 建议:≤900px 时隐藏该表(其信息与下方摘要卡完全重复)或改为卡片式单列布局。

**m3. 工作台"有问题"区以裸 task UUID 为条目主键,且与"等待我决定"区重复列同一事项**
- 位置:d1/m1/m3/p1 截图工作台下部;渲染在 `web/dashboard.js`(工作台聚合)。
- 问题:同一决策同时出现在"等待我决定"卡片和"有问题"区;后者首行是 `task-b6693d96-17a3-…` 裸 UUID,普通用户既读不懂也无法区分两者差异。
- 建议:"有问题"区隐藏纯决策类条目(保留真正的失败/阻塞),或用需求原文替代 UUID 作主键。

**m4. "推进一拍"内部术语暴露在全局头部**
- 位置:d1/m1/m3/p1 顶部右侧;出处 `web/dashboard.js:2`(注释自述"两个写动作(开始处理 / 推进一拍)",对应 `/api/worker/tick`)。
- 问题:这是 Goal Loop tick 的运维操作,普通用户无法理解,且与"开始处理"并列易误触。
- 建议:移入"系统状态"运维区,或改为人话(如"立即检查进度")并与主按钮做视觉区分。

**m5. 时间线最后阶段"完成"徽章=等待中、注记=进行中,语义自相矛盾**
- 位置:d3/m2/p3 截图末行;渲染在 `web/goal.js`(阶段推导)。
- 问题:"完成(等待中)/进行中"三者并排,用户难以判断任务到底完没完。
- 建议:末阶段注记改为与任务状态一致的中文短句(如"任务进行中,尚未到完成阶段"),或直接复用任务状态徽章。

**m6. 决策卡主视图只有"采用推荐方案/稍后决定",拒绝入口藏在折叠面板内**
- 位置:d4/m4/p4 截图;实现 `web/decisions.js:72-78`("不采纳推荐(按其他方式处理)"按钮位于 `details.tech-details` 折叠区内)。
- 问题:拒绝按钮存在且文案合格,但折叠面板标题"查看其他方案与影响范围"读起来像纯信息,用户未必知道里面有第二个决定入口。
- 建议:pending 态下把"不采纳推荐"以次级危险按钮直接与"稍后决定"并列,或将折叠标题改为"其他方案、影响与拒绝选项"。

**m7. 决策 ID/任务 ID 等裸标识符出现在用户卡片区**
- 位置:d4/m4/p4 右上角 `dec-visual-d3`;d1/p1"有问题"区 task UUID。
- 问题:属标识符而非状态枚举,危害小,但位于用户主视图而非技术详情区。
- 建议:弱化为可复制的小字或移入展开区(决策卡内已有先例:受影响文件用 mono-sm 弱化)。

**m8. 时间戳统一带 UTC "Z" 后缀直出**
- 位置:全部页面的"数据读取时间/更新于/完成于/创建于"。
- 问题:`2026-11-12 05:08:32Z` 对普通用户是技术格式,且未转本地时区。
- 建议:`fmtTime` 转本地时区并去掉 Z(技术详情区可保留原样)。

**m9. AI 资源页"用量与预算"表最后一列表头被截断为"预"**
- 位置:d7-1440-models.png 中卡表格。
- 问题:列宽不足导致表头截字,语义不明(应为"预留")。
- 建议:加宽列或缩写为完整可见的两字表头。

**m10. 从项目卡点入的需求表单未预选该项目**
- 位置:d6b-1440-project-form.png;实现 `web/projects.js`(表单插槽)。
- 问题:用户刚点了"让 Relay 在这个项目里做什么?",下方下拉却仍显示"请选择一个项目",多一步无意义操作。
- 建议:点入时预选对应项目(保留可改)。

**m11. "Discovery" 内部代号出现在 AI 资源页标题与空态**
- 位置:d7-1440-models.png("最近的需求分析(Discovery)"/"尚无 Discovery 记录")。
- 问题:属内部功能代号;该页虽是运维页,但标题已用中文"需求分析",括号代号反而添乱。
- 建议:标题保留中文,代号移到技术详情或删除。
