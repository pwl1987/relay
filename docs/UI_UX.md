# Relay Web / CLI / API 用户体验与交互规范

状态：**FROZEN（用户任务、关键状态可见性） / OPEN（UI 视觉、组件细节）**。P0 不建设大型多 Agent 可视化控制台。**实现注记（2026-11-14）**：主交互已由 WEB-UX-03 系重构为会话式工作区 `/workspace`（对话流+内联 Decision/Result），§2 的"P0 四个最小页面"为历史设计（Dashboard 降级、Decision Inbox 降为全局 Inbox），以 WEB-UX-03 合同与 03C.1/03D 交付为准；§1 原则与状态枚举仍有效。

## 1. 用户体验主原则

- **目标而非角色**：用户看到“要交付什么”“已验证到哪”“为什么停止”，不必管理 AI PM/架构师/开发员角色对话。
- **推荐而非问卷**：输入自然语言后优先自行调查和提供一个合理方案；只有 D3/无法调查的重要事实才问一个必要问题。
- **事实而非庆祝**：提交代码≠完成；区别 `构建完成`、`测试通过`、`已交付`、`运行健康`。
- **安全默认**：审批表述要写明动作对象、影响、成本、可逆性、超时策略，不能含糊“同意继续吗”。
- **渐进披露**：普通用户先看结果/证据摘要，专家按需展开 Run 日志、Diff、原始 Request、Gate 和 Audit。

## 2. P0 四个最小页面

### A. 首页 Dashboard

显示：当前 Project/Goal 数、Ready/Running/Blocked/Needs Decision、最后真实进展时间、最近已验收 ChangeSet、运行状态（含数据库/Worker/Provider）、预算消耗与风险告警。提供：新建 Goal、查看待决定事项、暂停全部**新**任务（不默默杀死有副作用命令）。

空状态要有意义：`没有符合权限/预算的 Ready Task，当前安全空闲`。不要显示虚构“Agent 24h 努力中”。

### B. Goal 详情/新建

新建字段：项目、原始话语（允许只有一句模糊话）、预期结果（可空）、约束、授权级别、预算上限。提交后展示 Discovery：理解的问题、可核查证据、替代方案、推荐下一步、关键假设、需要用户决定的项目。

详情顺序：目标和验收 → 当前阶段/进展 → 阻塞原因/下一动作 → Task/ChangeSet → 证据/预算历史。可执行 Pause/Resume，必须带版本检查与幂等处理。

### C. Decision Inbox

列表按风险/截止时刻排序；每项显示：推荐、为什么、备选、影响文件/系统、是否可逆、成本/回滚、超时的默认行为和影响范围。

动作：批准、拒绝、选择更保守路径、推迟。D3 永不有“超时自动通过”选项。批准要求确认具体的命令/作用域/时间窗口，不能无限期开放凭据。

### D. ChangeSet / Evidence

显示：影响仓库与文件、base/result SHA、Diff 摘要、独立 Reviewer 判断、真实测试、失败与重试、Gate 结果、交付目标。状态分明：
- `SUBMITTED`：Agent 提交但未验证；
- `REWORK`：存在可重现失败；
- `VERIFIED`：当前提交通过适用 Gate；
- `DELIVERED`：按授权成功集成；
- `BLOCKED` / `UNKNOWN`：缺少权限/外部结果不确定；
- `ACCEPTED`：Goal/Project 成果满足最终验收（区别任务验证）。

若因提交变化使证据失效，要显示“证据来自旧 SHA，需要重验”，不能继承绿色状态。

## 3. 关键用户流程（端到端页面）

- **模糊需求**：首页输入“感觉不好用”→确认 Project→自动生成问题理解和推荐→用户若无明确答案，可先授权沙箱原型→真实 Playwright 测试→候选更改→审批/交付。
- **长时间无人工响应**：Decision D3 待定→不相关 Task 继续→首页显示独立进展与阻塞原因→用户返回后针对未过期范围审批。
- **恢复**：Worker 失联→Run 显示 `NEEDS_RECONCILE`→展示上次动作意图及外部核查→核查可继续或人工处理，禁止自动装作成功。
- **被拒操作**：Agent 试图访问禁止路径→Policy DENIED→Audit/Goal 显示“本任务未获该权限”，避免显示无上下文错误码。

## 4. CLI 与 API 对等

P0 以 CLI 快速验证逻辑，UI/API 调用同一后端 Use Case。CLI 参考：`relay goal create --project xxx --input "..."`、`relay goal show`、`relay decision list`、`relay decision resolve`、`relay pause/resume`、`relay doctor`。具体命令及参数在首个实现包写单元和端到端合同测试，不在设计阶段假装已经有二进制。

## 5. P0 UI 验收清单

使用真实浏览器完成：创建 Goal → 查看推荐和任务 → 模拟 D3 待定/到期 → 查看另一个任务继续 → 触发失败 → 看见错误证据/恢复 → 审批已验证 ChangeSet → 展示 SHA 与交付结果。须点击、输入、捕获 HTTP、截图和交互的真实返回。仅截图漂亮但 API 不工作不算通过。

P0 可用 React/Vite，组件库及品牌风格 OPEN。优先可读性、键盘操作、狭窄窗口、错误恢复；移动端响应式 P1 深化。不做拖拽多 Agent 流程图或复杂时间轴作为 MVP 前提。
